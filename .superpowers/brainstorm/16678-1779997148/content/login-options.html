¿Cómo estructurar el Login de Médicos?

Selecciona la opción que prefieras para el flujo de autenticación de médicos y pacientes.

A

Pestañas en la misma página de Login

Una única página /login con pestañas "Pacientes" y "Médicos":

  • Pacientes: Inician sesión con Tipo/Número de Documento + Contraseña.
  • Médicos: Inician sesión con Correo Institucional + Contraseña.
  • Ventaja: Dirección única de ingreso, fácil de encontrar.
  • Desventaja: Mezcla la interfaz pública del paciente con la del profesional.
B

Página de Login Independiente (Recomendada)

Una página totalmente separada para el personal de salud (ej: /medico/login):

  • Pacientes: Siguen usando la página /login tradicional.
  • Médicos: Entran a través de un enlace de "Portal Médicos" en el header/footer hacia /medico/login.
  • Ventaja: Completa separación de flujos y branding profesional. Permite simplificar las rutas y layouts.
  • Desventaja: Los médicos deben navegar al portal específico de salud para iniciar sesión.

Detalles Técnicos Propuestos

Beneficios de la Separación

  • Diferentes formularios (Documento vs Email).
  • Protección de rutas limpia mediante roles (RoleRoute).
  • Evita confusiones de usuario al intentar usar credenciales equivocadas.

Consideraciones a Resolver

  • Necesidad de guardar el rol (rol: 'medico' | 'paciente' | 'admin') en el store de autenticación (Zustand).
  • Mapear el medico_id de base de datos desde el token JWT.
